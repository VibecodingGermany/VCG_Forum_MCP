# Builder report — VCG Forum MCP wrapper

## What I built

A thin, dependency-light Node ESM wrapper (`@vibecoding/forum-mcp`) around the official,
pinned `@discourse/mcp@0.2.9` package, per the architect brief
(`reports/v0.1.0/sprint-02/01-architect-report.md`). No Discourse/MCP logic is reimplemented —
the wrapper only bakes config and spawns the official binary.

- **`package.json`** — `type: module`, `bin: vcg-forum-mcp -> src/cli.js`, `engines.node >=18`,
  `files: [src]`, exact-pinned `@discourse/mcp: 0.2.9` as the sole dependency, MIT license,
  `repository: github:VibecodingGermany/VCG_Forum_MCP`.
- **`src/config.js`** — baked `SITE`, profile-path resolver (`${XDG_CONFIG_HOME||~/.config}/vcg-forum-mcp/profile.json`),
  `ensureConfigDir()` (mkdir `0700` + enforced chmod), `lockDownProfileIfPresent()` (chmod `0600`
  after login), `profileExists()`. Never reads/logs profile contents.
- **`src/discourse.js`** — resolves the installed `@discourse/mcp` binary via `createRequire`
  (no npx, no re-download) and spawns it with `spawnSync(process.execPath, [binAbs, ...args], { stdio: 'inherit' })`,
  propagating the child's exit code.
- **`src/commands/login.js`** — prints the browser-first / Clerk SSO notice, ensures the config
  dir, spawns `generate-user-api-key --site <SITE> --application-name "VCG Forum MCP" --save-to <PROFILE>`,
  chmods the profile to `0600` on success, prints only the profile *path*, and mentions the
  `allow_user_api_key_scopes` admin requirement for write access.
- **`src/commands/serve.js`** — errors cleanly (exit 1) with a "run login first" message when no
  profile exists; otherwise spawns `--site <SITE> --profile <PROFILE>`, adding
  `--read_only=false --allow_writes=true` only when `--write` or `VCG_FORUM_MCP_ALLOW_WRITES=1`
  is set; forwards passthrough args.
- **`src/commands/config.js`** — prints a `claude mcp add` command and a `.mcp.json` snippet in
  both read-only and write variants, plus the `npx -y github:VibecodingGermany/VCG_Forum_MCP`
  and future `npx -y @vibecoding/forum-mcp` install forms.
- **`src/commands/help.js`** — usage text, including the security note that the key is never
  printed/logged.
- **`src/cli.js`** — entrypoint (`#!/usr/bin/env node`, executable/`chmod +x`) routing
  `login|auth`, `serve` (default when no args), `config|print-config`, `help|--help|-h`,
  `--version` (read from `package.json` via `createRequire`), and unknown-command handling.

### Security posture implemented
- The User API Key / profile contents are never printed, logged, or written by this wrapper
  itself — only the official `@discourse/mcp` tool writes the profile file, and this wrapper
  only ever surfaces its *path*.
- Config dir is created/enforced at `0700`; profile is chmod'd to `0600` after a successful login.
- Write access is off by default; requires explicit `--write` flag or
  `VCG_FORUM_MCP_ALLOW_WRITES=1`, and is documented as also requiring the forum's
  `allow_user_api_key_scopes` admin setting to include `write`.
- No network calls, telemetry, or analytics of the wrapper's own.
