## Executive Summary

**Verdict:** Build fresh OR adopt the official Discourse MCP as a reference.

An **official Discourse MCP server** exists and is actively maintained by the Discourse core team (Sam Saffron). It is the most complete, well-supported, and feature-rich implementation available. All community implementations are either older, less feature-complete, or specialized variants.

**Key Finding:** The official implementation at [`github.com/discourse/discourse-mcp`](https://github.com/discourse/discourse-mcp) **already supports per-user authentication** (via User API Keys) and **optional write capabilities**—your hard requirements are met by the official library.

## Discourse MCP Candidates Found

### 1. **discourse/discourse-mcp** (Official)

**Repository:** [`github.com/discourse/discourse-mcp`](https://github.com/discourse/discourse-mcp)  
**npm Package:** [`@discourse/mcp`](https://www.npmjs.com/package/@discourse/mcp) v0.2.7 (published 25 days ago)  
**Maintainer:** Discourse Inc. (Sam Saffron, core team)  
**Language:** TypeScript 85.9% | JavaScript 14.1%  
**License:** MIT  
**Last Activity:** 65 commits on main branch; active development as of July 2026  

#### Key Features
- **Read Operations:**
  - `discourse_search` — query topics/posts across forums
  - `discourse_read_topic`, `discourse_read_post` — retrieve full content
  - `discourse_get_user`, `discourse_list_user_posts` — user data
  - `discourse_filter_topics` — advanced filtering
  - `discourse_get_chat_messages` — chat message retrieval
  - `discourse_list_categories`, `discourse_list_tags` — list content

- **Write Operations (opt-in):** Create posts, topics, categories, users; file uploads; draft management
  - Disabled by default; requires `--allow_writes --read_only=false`
  - Rate-limited (~1 req/sec)

#### Transport
- **stdio** (default) — MCP standard for local agents
- **HTTP** — for remote/cloud deployment (Supabase Edge Functions, Cloudflare Workers compatible)

#### Authentication (Per-User Support: ✅ YES)
- **User API Key** (per-user, recommended):
  - Generated by individual users (no admin required)
  - User-specific permissions and rate limits
  - Expires after 180 days of inactivity (configurable per site)
  - Uses headers: `User-Api-Key` + `User-Api-Client-Id`
  - Built-in generator command for easy onboarding

- **Admin API Key** (admin-only):
  - Full system permissions
  - For site-wide operations

- **HTTP Basic Auth** (for reverse-proxied sites)

- **No Auth** (read-only mode, recommended for testing)

#### Read/Write Policy
- **Default:** Read-only mode (safe by default)
- **Opt-in Writes:** `--allow_writes` + `--read_only=false` + auth credentials
- **Configuration:** CLI flags or profile JSON

#### Official Announcement
[Discourse Blog (Oct 2025): "Discourse MCP is here!"](https://blog.discourse.org/2025/10/discourse-mcp-is-here/)
> "After community requests for an official MCP server for Discourse, the company introduced the Discourse MCP CLI to quickly deliver something useful to their diverse user base."

#### Fork Verdict: **REFERENCE-ONLY** (🚫 Do NOT fork)
**Rationale:**  
- This IS the official implementation maintained by Discourse Inc.
- Forking would split efforts and lose upstream updates
- All hard requirements (per-user auth, read-write, multiple platforms) are met
- Active maintenance; v0.2.7 from July 2026

**Recommendation:** Adopt directly via npm (`npx @discourse/mcp@latest`) or GitHub; submit issues/PRs upstream if customization needed.

## Key Findings

### ✅ Hard Requirements Met by Official

1. **Per-User Authentication:** ✅ User API Keys (individual users, no admin required)
   - Generated via built-in command or user settings
   - User-specific permissions and rate limits
   - Auto-expire after 180 days of inactivity

2. **Read-Write Capability:** ✅ Optional write tools
   - Default: read-only (safe)
   - Enable with `--allow_writes --read_only=false` + auth
   - Rate-limited; moderation-friendly

3. **Multi-Platform Support:** ✅ Proven
   - Claude Desktop
   - Claude Code (local MCP support)
   - Gemini CLI
   - LMStudio (local models)
   - ChatGPT (Developer Mode)
   - Compatible with VPS, Supabase Edge Functions, Cloudflare Workers

### 🎯 Deployment Recommendations for VCG Forum

Given VCG self-hosts Discourse on Ubuntu + Docker VPS:

#### Option A: Deploy Official CLI Directly (Recommended)
```bash
npx @discourse/mcp@latest \
  --site https://forum.yourorg.com \
  --auth_pairs '[{"site":"https://forum.yourorg.com","api_key":"...","api_username":"..."}]'
```
- Simplest; no customization needed; inherits all upstream updates
- Use User API Keys for per-user access
- Pair with your VPS's existing auth system

#### Option B: Docker + Official Package (For Containerization)
- Use official npm package; build Docker image locally
- Supports both stdio (local agents) and HTTP (cloud agents)
- Ideal if Supabase Edge Functions or Cloudflare Workers call the MCP

#### Option C: Extend Official (If Moderation is Critical)
- Start with official; fork only if you need features like review queue access
- Contribute extensions back to upstream
- Example: devzspy's moderation tools could be merged upstream

### ⚠️ Why NOT Fork

1. **Maintenance burden:** You inherit all security patches and bug fixes manually
2. **Divergence risk:** The official is actively developed; staying in sync is costly
3. **Community fragmentation:** Each fork splits adoption and support
4. **Zero added value observed:** Community forks are either inactive (AshDevFr) or direct copies (mcp-research)

**Exception:** Only fork if you have a specialized requirement (e.g., moderation integration) that upstream refuses. Even then, contribute the feature back.
